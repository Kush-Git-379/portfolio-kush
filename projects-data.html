Investment Portfolio Analyzer, OOP & Financial Metrics in Python

A Python-based investment portfolio analysis tool that reads a synthetic multi-asset portfolio from CSV, models each investment using an OOP inheritance hierarchy, computes portfolio-wide financial metrics, and produces visualizations and a written summary report. The system follows a four-stage pipeline: CSV ingestion via pandas, OOP modeling (Investment base class with Stock, RealEstate, BankDeposit, MutualFund, and DebtBond subclasses), statistical analysis with NumPy, and chart generation with Matplotlib. Each subclass inherits computed_growth(), predict_value(), and info() methods, making the system extensible to new asset types without modifying core logic.

Data Science · BI KNIME · Tableau DAV · Semester 5 · Oct 2025

Credit Risk Analysis & Stakeholder Dashboard; KNIME & Tableau

End-to-end credit risk analysis pipeline on a 100,000-record Kaggle credit scoring dataset (28 features, three-class target: Good / Standard / Poor). KNIME Analytics Platform was used for preprocessing, including missing salary imputation from annual income, median imputation of delayed payments, data type correction, and credit history age parsing, followed by decision tree classification. Tableau was used to build stakeholder-specific dashboard views, explicitly designed around the analytical questions of three different business teams: Sales & Marketing, Risk Management, and Product Development.

Stakeholder-Driven Dashboard Design

  • Sales & Marketing view: treemap of credit score distribution by occupation; bubble chart of average customer age per credit score category
  • Risk Management view: Sankey diagram mapping credit score → payment behavior flow; bar chart of credit utilisation ratio per payment pattern
  • Pearson correlation heatmap surfaces relationships between outstanding debt, interest rate, and credit utilisation ratio
  • Visual segmentation achieves classification without ML models: the occupation treemap inherently groups professions by dominant credit score
  • Future scope: Logistic Regression, Random Forest, XGBoost for automated scoring; Explainable AI (XAI) for regulatory compliance

Computer Vision · AR OpenCV · Python Sep 2025 · Nirma University

Real-Time Virtual Try-On of Color-Adjustable Sunglasses using OpenCV

A real-time augmented reality virtual try-on system for sunglasses built entirely using classical computer vision, no deep learning or GPU required. The system detects faces and eyes via Viola-Jones Haar Cascade classifiers, estimates geometric pose from inter-pupillary distance and eye midpoint coordinates, and overlays a sunglasses model scaled and rotated to match head tilt. A key differentiating feature is on-the-fly color customization via HSV hue shifting; the hue channel is shifted modulo 180 while preserving brightness and the alpha channel, allowing seamless cycling through the full color spectrum without reloading assets. Frame-to-frame jitter is suppressed using Exponential Moving Average (α = 0.2) as a temporal low-pass filter on all positional parameters.

Technical Pipeline

  • Preprocessing: CLAHE (Contrast Limited Adaptive Histogram Equalization) enhances local contrast under varying lighting without amplifying noise
  • Detection: Viola-Jones Haar Cascade for face, then eye detection restricted to face ROI, reduces search space and improves accuracy
  • Pose estimation: scale from Euclidean inter-pupillary distance; rotation via atan2 on eye center coordinates; position at eye midpoint
  • Color customization: BGR→HSV conversion, hue channel shift (mod 180), alpha channel preserved and restored after conversion
  • Temporal smoothing: EMA with α=0.2 on x, y, scale, and rotation, eliminates jitter without introducing lag
  • Per-pixel alpha blending for seamless compositing of glasses onto live video stream

Student Information System: Python & CSV

A command-line records system, written while I was still learning Python properly. Student data is stored in CSV files and all CRUD operations, add, view, search, update, and delete; are supported with field-level input validation for name, class, roll number, DOB, gender, and phone number. The terminal UI uses colour-coded output via termcolor and formatted table display via PrettyTable, with automatic duplicate header removal during CSV write operations.

Technical Design

  • Full CRUD via CSV, append on add, full rewrite on update/delete to maintain data integrity
  • Field-level validation: name (letters only), class (1–12), roll number (numeric), DOB (DD/MM/YYYY), phone (10 digits)
  • Duplicate header removal, raw_data.csv is deduplicated into students.csv on every write
  • Search by roll number with formatted PrettyTable output
  • Colour-coded terminal UI using termcolor: green for success, red for warnings, cyan for prompts

Machine Learning 1CS101 · Semester II · Apr 2024 First ML Project

IPL Match Winner Prediction using K-Nearest Neighbours

My first machine-learning project, from second semester. Predicting IPL winners from four features, which turns out to be about as hard as it sounds. The dataset (636 matches, 6 columns from Kaggle) uses four features: Team 1, Team 2, Toss Winner, and Toss Decision. A KNN classifier with K=9 and Euclidean distance was implemented in Python after categorical encoding. The model achieved 57.81% accuracy, interpreted as reflecting cricket's inherent unpredictability rather than model failure, given only four input features and no player statistics, venue, or pitch condition data.

Results & Observations

  • Overall accuracy: 57.81% on historical IPL data (636 matches)
  • Strong performers: Mumbai Indians (precision 0.64 / recall 0.74), Kolkata Knight Riders (0.65 / 0.73)
  • Per-team variance reflects sample size imbalance; Kochi Tuskers Kerala (few matches, perfect 1.0/1.0) vs Rising Pune Supergiant (0.0/0.0)
  • Feature limitation identified: toss outcome alone is a weak predictor; player form, venue, and pitch conditions would substantially improve accuracy
  • Toss Decision column had 21 null values, imputed with most frequent value ("field") as preprocessing step
